= Introduction to OpenShift Lightspeed
:navtitle: Introduction to OpenShift Lightspeed

In the previous section, you used GitOps to deploy and manage applications across your managed clusters. Now that you have workloads running across your fleet, a natural question arises: how do you quickly check on the state of those resources without logging into each cluster individually?

As the number of managed clusters grows, so does the cognitive load on platform engineers. Constructing manual search queries and sifting through scattered cluster outputs to answer fleet-wide questions can be time-consuming, especially during critical incidents. What if you could ask your fleet a question in plain English and get an immediate, actionable answer?

This is where *OpenShift Lightspeed* and the *RHACM Search MCP Server* come in.

== Concepts & Architecture

*https://www.redhat.com/en/technologies/cloud-computing/openshift/lightspeed[OpenShift Lightspeed]* is Red Hat's AI-powered assistant built into the OpenShift Console. It helps administrators interact with their clusters using natural language -- answering questions, explaining resources, and guiding troubleshooting. OpenShift Lightspeed works out of the box for single-cluster queries, leveraging its built-in tools to read resources directly from the cluster it runs on.

However, in a multicluster environment managed by RHACM, administrators often need to query resources running across their _entire fleet_ -- not just the hub cluster. This is where the *MCP Server for Red Hat Advanced Cluster Management* extends OpenShift Lightspeed's reach.

=== What is the Model Context Protocol (MCP)?

The https://modelcontextprotocol.io/[Model Context Protocol (MCP)] is an open standard that bridges AI models and external data sources. Think of it as a universal connector: it allows an AI assistant to discover and interact with tools exposed by external services, without requiring custom integrations for each one.

In our case, the MCP server translates natural language prompts into structured search queries against the RHACM Search API, enabling OpenShift Lightspeed to query resources across all your managed clusters from a single chat interface.

=== How it works

Here's the flow when you ask a fleet-wide question:

. You type a natural language question in the OpenShift Lightspeed chat (e.g., _"Are there any failing pods in my production cluster?"_).
. OpenShift Lightspeed sends the query to the MCP server.
. The MCP server translates it into an RHACM Search API query and executes it against the hub cluster.
. The structured results are returned to the LLM for analysis and presented back to you as a conversational response.

This means you no longer need to construct manual search queries or log into individual clusters to investigate issues. The entire fleet becomes queryable through a single conversational interface.

NOTE: The RHACM Search MCP Server is currently a *Technology Preview* feature. For more information, refer to the https://github.com/stolostron/search-mcp-server[MCP server repository].
